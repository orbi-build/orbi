## 准备工作

你需要一个已安装 Orbi 的 GitHub 仓库和 z.ai API key。在
[z.ai 控制台](https://z.ai/manage-apikey/apikey-list)创建 key。不要把它
放进 Git、Issue、PR 或 journal。

本次配置使用：

- endpoint：`https://api.z.ai/api/paas/v4`
- 模型：`glm-5.3-flash`
- API：`openai-completions`
- 认证：`Authorization: Bearer <key>`（Pi 会从 `apiKey` 发送）

## 配置

复制 provider 模板，或者创建 `.orbi/pi-providers.json`，完整内容如下：

```json
{
  "providers": {
    "z-ai": {
      "baseUrl": "https://api.z.ai/api/paas/v4",
      "api": "openai-completions",
      "apiKey": "$ZAI_API_KEY",
      "models": [
        {
          "id": "glm-5.3-flash",
          "name": "GLM 5.3 Flash",
          "contextWindow": 131072,
          "maxTokens": 32768
        }
      ]
    }
  }
}
```

创建本地环境文件。只在本机替换占位符，不要提交生成的文件：

```bash
mkdir -p .orbi
printf '%s\n' 'ZAI_API_KEY=replace-with-your-key' > .orbi/env
chmod 600 .orbi/env
```

在 `orbi.toml` 中选择精确的 provider 和模型：

```toml
pi_providers = ".orbi/pi-providers.json"
pi_provider = "z-ai"
pi_model = "glm-5.3-flash"
```

手动 tick 时，systemd 不会加载 `.orbi/env`。先导出变量，校验配置，再使用
上手指南中的正常命令：

```bash
set -a
. .orbi/env
set +a
orbi check --config orbi.toml
orbi --config orbi.toml
```

`orbi check --config orbi.toml` 只做校验、不发真实请求：前置命令、
`gh` 认证、provider 文件、选中的 provider/model 以及 `ZAI_API_KEY` 引用；
失败时会打印 `reason=` 和 `fix=`。第一次真实请求发生在第一次 run 里——用
`orbi status --follow` 跟踪它。

裸 `pi --print` 对这套配置**不是**检查：它用 Pi 自己的 agent 目录
（`~/.pi/agent`，设置了 `PI_CODING_AGENT_DIR` 时用该目录），永远不读
`pi_providers`——后者只通过 Orbi 为每次 run 物化的 agent 目录交给 Pi。
Runner 也会在启动时校验 JSON、选中的模型、endpoint 和 `ZAI_API_KEY`，不正确
就 fail fast。

## 踩坑记录

### 先确认 key 展开修复已经合并

PR #304 已合并，因此当前 `main` 包含 #303 修复。如果你使用的是较旧的
Orbi checkout，`$ZAI_API_KEY` 可能无法生效；先更新，不要把真实 key 写进
提交的 JSON。

### `session_pending` 不等于卡住

不要只按 phase 停留时长判断任务是否卡住。`session_pending` 表示 Pi 已启动、
但还没创建 session 文件，因此这个阶段没有可观察的 session JSONL。请看 journal
里的启动行 `process_spawned` / `session_created` / `first_request_started`，
确认 run 走到了哪个里程碑；session 已存在但还没有首个响应时是
`request_pending`。真正停滞的启动会由 Orbi 的恢复路径处理；不要自行添加
无限重试。

### 有意省略 reasoning 映射

可用的 provider 模板没有猜测 z.ai 专用的 reasoning 或 thinking-level 映射。
没有核实当前 Pi 和 z.ai 契约前，不要把 Gemini 的 `thinkingLevelMap` 复制过来。

## 额度用完后切哪一家

本文**未实测**确切的耗尽报错和恢复时间。保留失败 run 的证据，查看当前
z.ai 返回，然后为下一次运行手动切换；Orbi 没有自动 fallback。

替换 provider 文件和 key，并把两个 selector 改成匹配的值。例如 OpenRouter
模板使用：

```toml
pi_providers = ".orbi/pi-providers.json"
pi_provider = "openrouter"
pi_model = "google/gemma-4-31b-it:free"
```

设置 `OPENROUTER_API_KEY`，用 `orbi check --config orbi.toml` 校验精确
条目，把真实请求留给第一次 run（用 `orbi status --follow` 跟踪）。这个替代
路径的可用性和额度在本文中**未实测**。
