## Release notes

## Changelog

### Features

- orbi status shows as ready only an Issue the claim would pick ([Issue #1773](https://github.com/orbi-build/orbi/issues/1773); [PR #1780](https://github.com/orbi-build/orbi/pull/1780))
- One check decides whether a PR is Orbi's delivery: triage and the merge notification agree ([Issue #1776](https://github.com/orbi-build/orbi/issues/1776); [PR #1787](https://github.com/orbi-build/orbi/pull/1787))
- claim.py decides raise-or-skip for a failed read in one function ([Issue #1794](https://github.com/orbi-build/orbi/issues/1794); [PR #1797](https://github.com/orbi-build/orbi/pull/1797))
- delivery_labels.py computes "has a delivery state" once: is_pickup_eligible calls has_delivery_state ([Issue #1795](https://github.com/orbi-build/orbi/issues/1795); [PR #1796](https://github.com/orbi-build/orbi/pull/1796))

### Reliability and recovery

- CI-failure triage reads the delivery state from the engine: a blocked delivery no longer gets ai-fix-needed ([Issue #1771](https://github.com/orbi-build/orbi/issues/1771); [PR #1778](https://github.com/orbi-build/orbi/pull/1778))
- Label transitions clear the same queue label the claim uses, so a custom dispatch_label no longer survives a blocked terminal ([Issue #1775](https://github.com/orbi-build/orbi/issues/1775); [PR #1784](https://github.com/orbi-build/orbi/pull/1784))
- The effective review round after a recovery is decided once: review and failure reports agree ([Issue #1779](https://github.com/orbi-build/orbi/issues/1779); [PR #1781](https://github.com/orbi-build/orbi/pull/1781))

### Bug fixes

- Failure comments show the current PR's review round, the same one review uses ([Issue #1772](https://github.com/orbi-build/orbi/issues/1772); [PR #1777](https://github.com/orbi-build/orbi/pull/1777))
- orbi status shows exactly the claim's decision: same held deliveries, and a failed release milestone read is a failed read ([Issue #1782](https://github.com/orbi-build/orbi/issues/1782); [PR #1791](https://github.com/orbi-build/orbi/pull/1791))
- A failing review round reports the round it ran, not one re-derived from the scene it just advanced ([Issue #1783](https://github.com/orbi-build/orbi/issues/1783); [PR #1785](https://github.com/orbi-build/orbi/pull/1785))
- A CI failure never relabels a terminal Issue: the fix-needed label transition is the one decision ([Issue #1786](https://github.com/orbi-build/orbi/issues/1786); [PR #1790](https://github.com/orbi-build/orbi/pull/1790))
- Branch reclaim and the orphan-PR sweep use the one delivery-branch check: a non-Orbi branch is never deleted ([Issue #1788](https://github.com/orbi-build/orbi/issues/1788); [PR #1789](https://github.com/orbi-build/orbi/pull/1789))
- The opened-PR scan finds the oldest free candidate even when older ones are skipped ([Issue #1792](https://github.com/orbi-build/orbi/issues/1792); [PR #1793](https://github.com/orbi-build/orbi/pull/1793))
