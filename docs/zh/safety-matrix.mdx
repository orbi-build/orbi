每一行写明一种故障、拦住它的那一层、Runner 的实际动作，以及证明它的测试。

本页是索引，不是第二份说明。机制本身写在它该在的地方：[安全](/zh/security)、
[工作流](/zh/workflow)和[运维](/zh/operations)。本页多出来的是最后一列：
`tests/test_docs_safety_matrix.py` 会收集这一列写到的每个测试 id，测试被改名
或删除时，测试套件直接失败，不会留下一条没人能核对的说法。

## 如何阅读

- **证明它的测试**是一个 pytest id，可以用
  `python3 -m pytest "<id>"` 单独运行。
- 证明的范围就是该测试断言的内容，不会更宽。多数测试用 fake 或本地 Git
  仓库驱动 Runner，并不证明线上部署、真实的 GitHub 凭据，或你的仓库的分支规则。
- `(no test)` 表示这个行为没有测试证明。每一个这样的行都会在
  [已知缺口](#已知缺口)里再列一次。

## 已知缺口

这些是维护者目前接受的限制。列在这里并不代表承诺会补上。

- **Runner 不会拦住 agent 会话推送受保护分支** — `(no test)`。实现者和评审者
  使用这台机器的 Git 凭据运行。“不 merge、不 push base 分支”是 prompt 契约；
  真正执行拦截的是你仓库上的 GitHub branch protection 或 ruleset。没有配置时，
  Orbi 内部没有任何机制能阻止它。
- **发版不经过审查门禁。** 发版任务按自己的门禁把版本提交直接推送到 base 分支
  （见[工作流](/zh/workflow#epicrelease-task-与-p0-优先级)）。上面的各行只描述
  开发交付。
- **需要人决定的 verdict 离不开维护者。** 评审者返回
  `blocked_on_human_decision`，或轮次预算用尽时，Runner 停下且不 merge。需要有人
  做出决定，然后手动 merge、把 Issue 改标为 `ai-fix-needed` 让同一个 PR 带着新的
  轮次预算继续，或者重新派发。停下这一步由
  `tests/test_review_merge.py::test_review_and_merge_human_decision_stops_without_fix_round`
  证明；决定本身没有任何自动化（即 Issue #1099 和 PR #1100 背后的情形）。
- **`/slots` 探测需要主动开启。** `model_wait_probe_url` 未设置时，被吞掉的请求
  只能靠更长的 `model_wait_dead` 阈值发现。
- **`allow_stale_runner` 会把新鲜度门禁变成警告。** 这是有意提供的主机侧开关，
  设置了它的部署等于放弃了第一行。
- **本地测试不是线上边界。** 没有任何一行证明真实的 GitHub 权限、真实的 systemd
  或 launchd 主机，或真实的模型端点。

提出本页需求时点名的两个缺口后来已经补上，保留在这里以便看清来龙去脉：

- 评审者过去只在 claim 时读取一次 Issue 正文（Issue #1094）。现在每一轮审查都会
  重新读取：
  `tests/test_bootstrap_runner_prompt.py::test_run_review_refreshes_issue_body_each_round`。
- resume 评论过去声称缺失的 worktree 会被重建，而代码从未重建（Issue #807）。现在
  worktree 会从远端分支重新创建：
  `tests/test_resume_pr.py::test_verify_resumed_pr_recreates_missing_worktree_from_remote_branch`。
  这条一般性的提醒仍然成立：评论里报告了恢复，不等于恢复真的发生了。
