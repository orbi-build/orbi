# OpenCode Zen provider

本文说明如何在 Orbi 中使用 **OpenCode Zen**（OpenCode 提供的精选模型服务），属于 [provider 文档 Epic（#305）](https://github.com/orbi-build/orbi/issues/305)。它与 OpenCode 终端应用的项目配置不同：Orbi 运行的是 Pi，不是 OpenCode。

> **证据边界——2026-09-07。** 以下检查使用已安装的 Pi CLI **0.85.1**。`pi auth check --provider opencode --json --no-refresh` 能识别 `opencode`，并返回 `credentials_not_configured`（退出码 1）。当前环境没有 OpenCode 账号或 API key，因此**未实测**真实模型请求、额度消耗以及 Orbi Issue 到 PR 的完整运行。不要把本文当作账号仍有可用额度的保证。

## 认证

OpenCode 官方流程是 API key 认证，不是 Orbi 发起的 OAuth 登录：

1. 打开 [OpenCode authentication](https://opencode.ai/auth)，登录，填写 billing 信息，创建并复制 OpenCode Zen API key。
2. 将 key 放入 Orbi 运行环境。推荐使用项目本地、权限为 600 的 `.orbi/env`（不会提交）：

   ```bash
   mkdir -p .orbi
   printf '%s\n' 'OPENCODE_API_KEY=replace-with-your-key' > .orbi/env
   chmod 600 .orbi/env
   ```

3. 派发 Issue 前检查凭据：

   ```bash
   pi auth check --provider opencode
   ```

   配置正确的 key 后，不应再返回 `credentials_not_configured`。此检查不消耗额度。可选的真实 smoke 请求（使用下面选择的精确 model）：

   ```bash
   pi --provider opencode --model glm-5.3-flash --print 'reply with: ok'
   ```

Pi 也有 API-key provider 的交互式 `/login` 流程，但这里不是必须的：`/login` 会把 key 存入 Pi 的 `~/.pi/agent/auth.json`，而 `.orbi/env` 方式让 Orbi systemd unit 显式加载凭据。不需要运行 OpenCode OAuth，也不需要在 Orbi 使用 Pi 时填写 OpenCode 的 `~/.local/share/opencode/auth.json`。

## Pi 与 Orbi 配置

Pi 0.85.1 原生提供以下 provider 契约：

- provider：`opencode`
- API key：`OPENCODE_API_KEY`
- 服务 endpoint：Pi 内置的 OpenCode Zen endpoint
- 支持的 API：原生 Anthropic Messages、Google Generative AI、OpenAI Completions 和 OpenAI Responses adapter，由 catalog 条目选择

因此 **不要为 OpenCode 创建 `pi_providers.json`**，也不要把 OpenCode 条目复制到第二个 provider 文件。`pi_providers` 用于自定义 provider；重复定义会过时且没有必要。

在 `orbi.toml` 中只设置选择项：

```toml
pi_provider = "opencode"
pi_model = "glm-5.3-flash"
```

保持 `pi_providers` 未设置。Orbi 已安装的 unit 会加载 `.orbi/env`；手动运行时 shell 不会自动加载它，所以先导出变量：

```bash
set -a; . .orbi/env; set +a
orbi --help >/dev/null
```

真实派发前运行 `orbi setup`/正常配置校验。所选 provider 和精确 model 必须存在于 Pi 当前 catalog 中。

## 额度、限流、重置与失败表现

根据 [Zen 官方文档](https://opencode.ai/docs/zen/)，Zen 按请求 pay-as-you-go，使用账号 credits，支持自动充值（余额低于 $5 时默认充值 $20，可配置或关闭），也支持 workspace 和团队成员的月度限额。官方没有承诺统一的免费额度或固定重置时间；限额和 model 可用性取决于账号、workspace 和 plan。标记为 `Free` 的若干模型也明确只是限时提供。

本次运行没有账号，以下内容因此**未实测**：剩余余额、请求速率限制、重置时间、额度耗尽时的 HTTP status/body，以及具体 plan 是否启用某个 model。凭据失败、model 被禁用、credits 耗尽或上游限流，都会表现为 Pi model request 失败；Orbi 必须让 run 失败，不能静默重试或声称 Issue 已到达 PR。检查去除秘密后的 Pi/Orbi 错误，再在 OpenCode 中核对 key、余额、workspace 限额、model access 和当前 catalog。

## 最小 fallback

保持 Issue 和 runner 不变，只修改 provider 选择（替代 provider 需要 secret 时一并修改）。切换到仓库现有的 local Qwen template：

```diff
 pi_provider = "opencode"
-pi_model = "glm-5.3-flash"
+pi_providers = ".orbi/pi-providers.json"
+pi_provider = "local-qwen"
+pi_model = "Qwen3.8-27B"
```

将 `templates/pi-providers/local-qwen.json` 复制为 `.orbi/pi-providers.json`，并确保本地 OpenAI-compatible server 正在运行。切换到 z.ai 时，复制 `templates/pi-providers/z-ai.json`，在 `.orbi/env` 使用 `ZAI_API_KEY`，并只将三个选择项改为 `pi_provider = "z-ai"`、`pi_model = "glm-5.3-flash"`。这些 fallback 各有自己的可用性和额度要求，并不保证有容量。
