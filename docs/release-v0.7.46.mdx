## Release notes

## Changelog

### Features

- Question ids are unique per Issue whichever stop writes them ([Issue #2227](https://github.com/orbi-build/orbi/issues/2227); [PR #2231](https://github.com/orbi-build/orbi/pull/2231))
- One question parser for drafting and stops: the recommended field counts in drafting too ([Issue #2228](https://github.com/orbi-build/orbi/issues/2228); [PR #2232](https://github.com/orbi-build/orbi/pull/2232))
- The stopped-ticket scan, the merge gate and the steering poll all act on the same answer, so answering the same stop question A then B carries out B at every stage. ([Issue #2233](https://github.com/orbi-build/orbi/issues/2233); [PR #2236](https://github.com/orbi-build/orbi/pull/2236))
- Finding the delivery PR uses the existing github.open_pr_for_branch with same-repository filtering, so a close_all answer never closes a cross-repository PR that shares the delivery branch name. ([Issue #2234](https://github.com/orbi-build/orbi/issues/2234); [PR #2237](https://github.com/orbi-build/orbi/pull/2237))
- Answer payload validation has a single implementation, so the duplicate validator is gone and src/orbi/answer.py gets shorter. ([Issue #2235](https://github.com/orbi-build/orbi/issues/2235); [PR #2238](https://github.com/orbi-build/orbi/pull/2238))

### Reliability and recovery

- Stops carry one structured question; a review deadlock with a recommended, non-authority option resolves itself once ([Issue #2220](https://github.com/orbi-build/orbi/issues/2220); [PR #2224](https://github.com/orbi-build/orbi/pull/2224))
- Carry out a person's answer to a stop question at every stage, and hold the merge when a newer answer changes the decision ([Issue #2221](https://github.com/orbi-build/orbi/issues/2221); [PR #2229](https://github.com/orbi-build/orbi/pull/2229))
- Classify failed releases, no-commit deliveries and no-file-change deliveries instead of unclassified ([Issue #2222](https://github.com/orbi-build/orbi/issues/2222); [PR #2226](https://github.com/orbi-build/orbi/pull/2226))

### Documentation

- Docs: a safety matrix (failure mode -> layer -> runner behaviour -> proving test) pinned by a test, with a Known gaps section ([Issue #1114](https://github.com/orbi-build/orbi/issues/1114); [PR #2215](https://github.com/orbi-build/orbi/pull/2215))
