$ orbi --help
usage: python3 -m orbi.cli [-h] [--config CONFIG] [--version]
                           {add,suggest,status,session,install-units,sync-engine-source,doctor,check,setup,fix-base,split,milestone,notify} ...

Orbi task dispatch and status CLI. With NO subcommand the CLI IS the Runner
entry: it runs one tick, exactly like `python3 -m orbi.runner` — this is what
the scheduler entry (the systemd service's `ExecStart` on Linux, the launchd
agent on macOS; the installed `orbi`) invokes on every trigger. The named
subcommands are the dispatch and debug entries on top of that: `add` creates
an Issue in a configured source repo and labels it `ai-ready`. `status`
reports the current in-progress Issue (with its live Pi activity: phase, last
activity time, the last meaningful action, the newest tool call result,
session file and worktree), the next ready Issue, and the most recent result
(`ai-pr-opened` / `ai-fix-needed` / `ai-merged` / `ai-blocked`) per source
repo. GitHub Issues and labels are the only state store. There is no database,
queue, or web UI. Command failures are logged and raised by the reused
runner.run_command; there is no fallback.

positional arguments:
  {add,suggest,status,session,install-units,sync-engine-source,doctor,check,setup,fix-base,split,milestone,notify}
    add                 create an Issue in a source repo and add ai-ready
    suggest             read the repository and propose up to three Issues to
                        deliver (interactive; --json prints the Suggestions
                        document)
    status              show every active delivery with attributed local
                        activity, ready queue and recent result per source
                        repo
    session             print the live Pi session JSONL path, or follow it
                        like tail -f
    install-units       idempotently install the repo's scheduler units
                        (systemd on Linux, launchd on macOS; never restarts a
                        running Runner)
    sync-engine-source  sync the deploy home checkout to the configured
                        engine_source_track (the service ExecStartPre runs
                        this on every tick; Issue #535)
    doctor              read-only report: repo commit, unit drift,
                        timer/service, slots, Pi, current Issue, recent
                        journal
    check               read-only prerequisite gate: python, commands, the
                        scheduler user session, gh auth, pi, config, repo
                        access, transport, model provider — fails fast with
                        reason, fix and official docs link (Issue #163)
    setup               one-time, idempotent initialization: gh auth + repo
                        permissions, platform labels, scheduler units,
                        checkout check and the optional model proxy (Issue
                        #117)
    fix-base            run the registered `/orbi fix-base` ticket command on
                        one Issue: the same rules and one receipt as the
                        comment
    split               run the registered `/orbi split` ticket command on one
                        Issue: the same rules and one receipt as the comment
    milestone           advance active_milestone (the manual command behind
                        the auto_next_milestone=false confirmation flow)
    notify              send notifications and check the notification setup

options:
  -h, --help            show this help message and exit
  --config CONFIG
  --version             show program's version number and exit
